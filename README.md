## ⭐ Featured: [LLM Gateway](https://github.com/BakdauletBolatA/llm-gateway)

An OpenAI-compatible gateway in front of **Anthropic, OpenAI and Ollama**. An app that calls one LLM provider inherits its bad days — latency tails, rate limits, outages and a bill nobody capped. The gateway puts one API in front of several providers and adds the mechanisms that keep requests alive and spending bounded, then measures what each mechanism is actually worth.

- **Reliability:** timeouts, retries with jitter, circuit breaker, fallback across API dialects, hedging, per-provider concurrency limits
- **Cost control:** spend tracking per key, model and route in PostgreSQL; a hard budget that refuses with `402` *before* the provider is called; rate limits shared across replicas
- **Smart routing and caching:** `model: "auto"` sends easy requests to a small model; opt-in response cache scoped per tenant and conversation
- **Observability:** Prometheus metrics, a provisioned Grafana dashboard, typed errors and per-request telemetry headers
- **Measured, not claimed:** a chaos harness with 11 failure profiles on a mock provider took success from **46% → 91%** and p95 in a failure storm from **20 s → 250 ms**; routing by complexity kept 28 of 30 held-out prompts correct (29 for always-large) at about a third lower modeled cost. Every number is regenerated by scripts in the repo

<sub>Python · FastAPI · httpx · PostgreSQL + pgvector · SQLAlchemy/Alembic · Prometheus · Grafana · Docker Compose — runs from a clean checkout with no API key</sub>
